# Комірка — прості таблиці для Android

Невеликий нативний офлайн-додаток українською мовою для збирання структурованих даних. Android 8.0 (API 26) і новіші. Без облікового запису, реклами, мережевих дозволів і бібліотек часу виконання.

## Встановлення

Готовий інсталяційний файл: **`artifacts/Komirka-1.0-debug.apk`**.

1. Скопіюйте APK на Android-телефон і відкрийте його.
2. Якщо Android попросить, дозвольте встановлення з вибраного файлового менеджера.
3. Відкрийте **Комірку** та натисніть **Створити таблицю** або **Імпортувати CSV**.

APK має тестовий підпис і призначений для прямого встановлення. Для публікації в Google Play потрібен власний release-підпис. Збережіть локальний ключ `.tools/debug.keystore`, якщо хочете встановлювати подальші тестові збірки як оновлення без видалення додатка.

## Що вміє додаток

- Створення кількох таблиць із назвою, описом і власними стовпцями.
- Типи **String, int, float, category, ordinal, bool, date**. `int` — знакове 64-бітне ціле; `float` — скінченне число подвійної точності.
- Категорії додаються по одній; порядок ordinal задається стрілками. Під час введення категорії вибираються кнопкою, довгі списки мають пошук.
- ID: без окремого стовпця, автоматичний UUID, автоінкремент 1, 2, 3… або ручний унікальний текстовий код.
- Покрокове введення: автоматичне відкриття текстової / числової клавіатури, кнопки **Так** і **Ні** з різними кольорами та підписами, календар, кнопка **Немає значення**.
- Повернення до попередніх полів і екран перевірки всього запису. Лише фінальна кнопка **Закінчити та додати до таблиці** створює рядок.
- Одна незалежна чернетка на таблицю. Збереження після введення та при виході; відновлення після перезапуску додатка.
- Перегляд записів картками або сіткою, пошук українською, сторінки по 40 записів, редагування й видалення.
- Історія / aliases для змінених значень, зокрема ручного ID: відновлення, заміна, видалення окремих значень або очищення історії поля. Редагування aliases також застосовується лише після фінального підтвердження.
- Експорт через системний вибір місця збереження; імпорт через системний вибір файлу. Доступ до всього сховища не потрібен.

## CSV та JSON

**CSV**: UTF-8 із BOM для українських символів, кома як роздільник, CRLF, стандартне екранування лапок і багаторядкового тексту. Перший рядок — назви стовпців. Експортуються тільки поточні значення. Відсутні значення й порожні / повністю пробільні поля — порожні клітинки; літеральні текстові `null` та `NaN` залишаються текстом. CSV не зберігає типи, категорії чи історію. Довільний текст, включно з формулами, передається без змін; відкриваючи зовнішні CSV у табличних редакторах, обирайте відповідні типи текстових стовпців.

**Імпорт CSV**: UTF-8, UTF-16 із BOM; роздільник визначається за заголовком (кома, крапка з комою, табуляція). Обробляються лапки, вкладені лапки, переноси рядків, порожні клітинки. Типи визначаються консервативно: коди з початковими нулями залишаються текстом. До імпорту можна змінити назви, типи, категорії та порядок стовпців. Наявний ID із файлу — звичайний стовпець; за потреби створюється додатковий автоматичний ID з іншою назвою. Дубльовані / порожні заголовки отримують унікальні назви, які можна відредагувати.

Імпорт атомарний: помилка містить номер CSV-запису й стовпець, а незавершена таблиця не записується. Порядок записів у CSV зберігається при повторному експорті; на екрані найновіші записи показуються першими. Ліміти: 10 МБ на CSV, 50 000 записів за один імпорт, до 100 стовпців разом із додатковим ID. Для внесення записів вручну ліміту кількості рядків немає.

**JSON**: об’єкт із `format`, `version`, `name`, `description`, налаштуванням `id`, описом `columns` і масивом `rows`. Кожен запис містить `values`, `aliases`, `createdAt`, `updatedAt`. У `values` числа й bool зберігають свій тип, пропуски — `null`; ordinal містить значення категорії, а її порядок записано в `columns[].categories`. Історія містить старе значення та `at` у мілісекундах Unix. JSON призначений для експорту й подальшої обробки; імпорт у цій версії підтримує CSV.

У папці `examples/` є CSV для перевірки імпорту. Назву й опис таблиці можна змінювати після створення. Структура завершеної таблиці фіксована; для зміни типів експортуйте CSV та імпортуйте його як нову таблицю.

## Зберігання

Приватна SQLite-база `komirka.db`: окремі таблиці для схем, записів і чернеток. Зміни рядка, aliases, лічильника ID та видалення чернетки виконуються в одній транзакції. Автоінкремент не витрачається на чернетки й не повторно використовує ID видалених записів. Ручні ID захищені унікальним індексом. Версії записів запобігають перезаписуванню новіших змін старою чернеткою.

Дані залишаються в пам’яті додатка. Автоматичний хмарний backup вимкнений. Видалення додатка чи очищення його даних видаляє локальну базу. Експортуйте важливі таблиці перед такими діями.

## Збірка

Проєкт можна відкрити в актуальному Android Studio. Потрібні **JDK 17+** (рекомендовано 21), **Android SDK Platform 36**, **Build Tools 36.0.0**. Gradle Wrapper: **9.2.1**, Android Gradle Plugin: **9.0.1**. Сумісність AGP перевірено за [офіційними нотатками Android](https://developer.android.com/build/releases/agp-9-0-0-release-notes).

Вкажіть шлях до SDK у `local.properties`:

```properties
sdk.dir=C\:/Users/YOUR_USER/AppData/Local/Android/Sdk
```

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

У цьому робочому середовищі є допоміжний запуск, який використовує локальну `.gradle-home`, наявний кеш залежностей і локальний тестовий ключ:

```powershell
pwsh -NoProfile -File tools/build.ps1
```

Результат: `app/build/outputs/apk/debug/app-debug.apk`. Release-збірка `assembleRelease` вмикає R8, але потребує власного підпису для встановлення / розповсюдження. Ключі й SDK не включаються до джерельного архіву.

## Перевірки

- JUnit: CSV, екранування, пропущені клітинки, Unicode, локальні дробові числа, діапазони, bool, ordinal, валідація й визначення типів.
- Robolectric з Android API 35: реальна SQLite, транзакції, ID, чернетки після закриття бази, aliases, конфлікти редагування, імпорт/експорт, порядок рядків, каскадне видалення.
- UI-сценарії в Android runtime: створення таблиці й ordinal, усі кроки запису, фінальне підтвердження, редагування й відновлення aliases, перезапуск Activity, повернення назад і null.
- Android Lint; рендери нативних екранів у `artifacts/screenshots/`.

Robolectric — тестове Android-середовище, а не фізичний телефон. Автоматична перевірка не замінює перевірку системної клавіатури й файлового діалогу на конкретному пристрої. Метод налаштування тестів відповідає [офіційній документації Robolectric](https://robolectric.org/getting-started/). Insets системних панелей та клавіатури враховано відповідно до [правил Android edge-to-edge](https://developer.android.com/develop/ui/views/layout/edge-to-edge).

## Структура

```text
app/src/main/java/ua/komirka/
  MainActivity.java       Навігація, перегляд, пошук, імпорт / експорт
  core/Models.java        Моделі, типи, схеми, записи, чернетки
  core/Values.java        Валідація, перетворення, визначення типів
  core/Csv.java           Незалежний CSV-парсер та writer
  data/Codec.java         Явна серіалізація JSON
  data/Store.java         SQLite й атомарні операції
  ui/Design.java          Нативні компоненти й візуальні стилі
  ui/SchemaEditor.java    Створення та налаштування таблиці
  ui/EntryEditor.java     Введення, перевірка, редагування aliases
app/src/test/             Автоматичні перевірки
examples/                 Приклади CSV
tools/build.ps1           Допоміжна збірка для Windows
```
